# Roadmap produit

**Principe :** capacité démontrable avant sophistication. Voir [périmètre](scope.md) et [plan technique](../04-execution/plan.md).

1. **P0** — Valider contraintes plateforme, sécurité, contrat d'adaptateur et deux CLI : impossible d'affirmer une reprise universelle.
2. **V1-A** — Collaborer : identité, projet, groupe, mention, exécution, réponse, état, audit.
3. **V1-B** — Produire : ticket, espace contrôlé, livrable Git, revue, verdict.
4. **V2** — Piloter davantage : connaissances/documents, équipe réutilisable, Kanban, jalons.
5. **V3** — Paralléliser proprement : isolation Git avancée, dépendances et validation technique enrichie.
6. **V4** — Automatiser avec délégation et limites.

## Conditions de passage
Chaque version doit avoir ses tests d'acceptation, un risque de sécurité évalué, une migration de données réversible ou sauvegardable et un retour utilisateur sur son cycle complet.

## Hors engagement
Aucune date ni charge n'est estimée : aucune équipe, dépôt, machine hôte ou contrainte budgétaire ne sont encore connus.
